# TenSnap Protocol v0.3

状态：定稿（v0.3 wire contract）。

本文定义 v0.3 的协议形状、跨端可观察行为和实现边界。规范中的
“必须（MUST）”“应当（SHOULD）”“可以（MAY）”用于区分强制要求、推荐行为和可选能力。

## 1. 唯一事实来源

`@tensnap/protocol` 是协议的唯一事实来源，范围同时包括：

- wire message、payload、codec 和可序列化值的定义；
- renderer 与 simulator 的状态机、生命周期、事务和错误行为；
- 内建 layer、action、chart、monitor、scene restore 的可观察语义；
- JSON/MessagePack 编码规则和跨语言 conformance fixtures。

落地时建议在本包中形成以下结构：

- `src/*.ts`：Zod schema、schema 推导类型和 codec；
- `BEHAVIOR.md`：正式的行为规范；
- `conformance/`：由各 renderer/runtime/binding 共同消费的协议轨迹；
- `dist/protocol-types.md`：从 schema 生成的派生文档，不是第二份事实来源。

`packages/core` 负责实现 renderer 行为，不得重新定义协议行为。Python、Go、Julia、
JS binding 可以保留语言原生类型和 helper，但它们必须由本包 schema、行为规范和
conformance fixtures 约束。仓库其他文档只能引用这里，不得补充相互冲突的协议语义。

## 2. 设计目标

v0.3 遵循以下原则：

1. 简单模型只需少量消息和默认值；复杂模型可以选择 action target/kwargs、monitor、
   scene restore 和 checkpoint 等能力。
2. 同步、恢复、chart 操作仍使用各自的专用 payload。不得为了方便把 `state_sync`、
   `scene_restore` 或 `chart_update` 塞进通用 action kwargs。
3. protocol 描述可观察行为，不把某个现有 binding 的偶然实现固化为规范。
4. 对省略、空集合、重复 ID、断线、事务失败、并发和能力缺失给出明确结果。
5. v0.2 向后兼容不是首要目标；但所有不兼容变化都必须在 v0.3 changelog 中列出。

非目标：

- 不在协议中定义 React 组件、项目窗口布局或具体 WebSocket 实现；
- 不要求所有模型都支持可逆映射或精确恢复；
- 不把 renderer snapshot 内部 storage shape 直接变成 wire payload；
- 不引入 action role。内建语义只由保留 action ID 表达。

### 2.1 最小模型 profile

一个最小离散模型可以只发布：

- 一条 capability list 为空的 `simulator_info`；
- 专用 state sync transaction；
- 一个 `continuous: true` 的 `step` action 和一个 `reset` action；
- 一个 environment/layer 及其 items；
- 每步后的 `metadata_update { time }`。

它无需实现 `start`、`stop`、monitor、scene restore、checkpoint、action target 或 kwargs。
renderer 用 `step` 同时完成单步和连续运行。v0.3 的可选能力不得增加此 profile 的实现负担。

## 3. 术语与所有权

- **simulator**：拥有权威模型状态，执行 action，发出状态变化。
- **renderer**：保存可渲染的同步状态、视图、chart 历史和 snapshot。
- **model**：一个稳定的模型种类，由 `model.id` 标识。
- **instance**：一次正在运行的权威模型实例，由 `instance_id` 标识。
- **view**：renderer 本地 UI 配置，不是协议对象。
- **project**：renderer 本地持久化对象，保存 source、view、scenario 和 snapshot。

协议不使用 transport 的 client/server 角色描述方向。即使某个部署中 simulator 是
WebSocket client，规范仍使用 simulator/renderer。

## 4. 基础数据与错误边界

普通协议值只能由 `null`、布尔值、有限数字、字符串、数组和 string-keyed object
递归组成。`undefined`、`NaN`、无穷值、函数、Symbol、Map、Set 和循环引用无效。
二进制只允许出现在 schema 明确声明的字段中；JSON transport 使用 base64 data URL，
MessagePack transport 使用 bytes。

### 4.1 Canonical snake_case 与 codec 薄兼容层

v0.3 的所有 core wire 字段统一使用 snake_case。TypeScript/Python/Go/Julia 的本地 API 可以
使用各语言惯用命名，但 codec boundary 上必须转换成 canonical snake_case。

codec 在每个 session 上只选择一次模式：

- peer `protocol_version >= 0.3`：关闭兼容层，encoder/decoder 只接受并输出 canonical v0.3；
  legacy alias 是 schema error，不能因为“恰好能转换”而接受；
- peer `protocol_version < 0.3`，或 legacy peer 没有提供 protocol version：启用薄兼容层；decoder
  在 schema validation 前把已知 v0.2 shape 映射成内部 canonical v0.3，encoder 仅在有无损
  映射时输出对应 v0.2 shape；
- 版本按解析后的 major/minor 数值比较，不能做字符串字典序比较；模式一旦选定，在同一
  transport session 中不得切换。

薄兼容层不是完整的 v0.2 polyfill。monitor、scene restore、action target/kwargs 等 v0.2
无法表达的能力必须被 capability gate 或返回 `unsupported_capability`，不能丢字段后继续。

当前 schema 中确定需要迁移的 camelCase 字段只有：

| v0.2 | v0.3 canonical | 兼容行为 |
| --- | --- | --- |
| parameter `allowRuntimeChange` | `allow_runtime_change` | decoder 按已知 parameter 路径改名 |
| action `allowRuntimeChange` | 删除 | decoder 丢弃并 warning，不映射到新字段 |
| chart group `dataList` | `data_list` | decoder 按 chart metadata 路径改名 |

兼容层必须是 path-aware 的薄转换，不能递归地把任意 object key 转成 snake_case。以下内容
可能合法包含 camelCase，必须原样保留：model ID 字符串、metadata、kwargs、monitor value、
item `data`、custom layer metadata 和所有模型自定义 map。

若 canonical 与 legacy alias 同时出现：值 deep-equal 时只保留 canonical 值并 warning；值不同
时拒绝整条消息，不能悄悄选择其中一个。JSON 与 MessagePack decode 后使用同一 normalization
函数。该规则只用于 `<0.3` legacy mode；`>=0.3` strict mode 不运行 normalization。

除 camelCase 外，v0.3 采用以下历史命名调整：

| v0.2 | v0.3 canonical | 决策 |
| --- | --- | --- |
| state sync `envs` | `envs` | 保留；`env` 是全局约定缩写 |
| `env_create/delete`、`env_layer_*` | 原名 | 保留 `env` 前缀 |
| `param_create/update/delete/sync/change` | 原名 | 保留 `param` 前缀 |
| `env_layer_create/update.data` | `metadata` | 采用；该字段实际不是 item data |
| `asset_meta` | `asset_metadata` | 采用；metadata 不缩写成 meta |
| `action_start` / `action_end` | `action_invoke` / `action_result` | 采用；避免与保留 action ID `start` 混淆 |
| action `tick_id` | `request_id` | 采用；它是 correlation ID，不只是 simulation tick |
| action result `continue` | `should_continue` | 采用；明确它只是 simulator 对下一次调度的建议 |
| `chart_delete { id }` | `chart_delete { kind, id }` | 采用；消除 group/series 歧义 |

legacy mode 必须使用精确 message type/field alias 表；不要实现通用字符串替换。所有新字段和
消息说明一律写 `metadata`，不得新造 `meta` 缩写。`mime`、item/asset/log 的 `data`、agent
`source/target` 等在各自上下文中含义清楚，继续保留。

v0.2 `chart_update.operations[].id` 没有足够信息推断 group 或 series，纯 codec 无法无损转换。
legacy decoder 应标记它为 legacy operation，renderer compatibility adapter 再按 v0.2 的
“group 优先，否则 series”规则解析；canonical v0.3 payload 必须始终显式提供 `kind`。

默认实现至少应施加以下可配置保护：

- 单条消息最大 16 MiB；
- monitor 当前值默认最大 4 MiB；
- object 最大嵌套深度 64；
- 单个集合默认最大 1,000,000 项。

超过 host policy 的消息必须被拒绝并产生结构化 `error`，不得部分应用。具体默认值可由
host 调低，simulator 可在 capability details 中声明更低限制。

v0.3 的错误 payload 建议扩展为：

```ts
interface ErrorPayload {
  code: string;
  message: string;
  request_id?: string;
  path?: string;
  retryable?: boolean;
  data?: unknown;
}
```

未知 core message type 是协议错误；未知的 namespaced extension message 可以忽略并记录
warning。create 已存在的 ID、update 不存在的 ID 是协议错误；delete 不存在的 ID 是幂等
no-op。一次事务中出现重复 ID 必须拒绝整个事务。

## 5. Simulator info、版本和能力

### 5.1 `simulator_info`

simulator 在 transport 打开后必须首先发送 `simulator_info`，renderer 在收到并验证之前
不得发送 `state_sync`、action 或 restore 请求。

```ts
interface SimulatorInfoPayload {
  protocol_version: "0.3";
  binding: {
    name: string;       // 例如 tensnap-python
    version: string;    // 发布版本
    language?: string;
  };
  model: {
    id: string;
    name?: string;
    description?: string;
    version?: string;
    state_schema_version?: string;
  };
  instance_id: string;
  capabilities: string[];
  capability_details?: Record<string, unknown>;
}
```

首批能力名建议为：

- `scene.restore.projected`：可从 params/time/完整 environment 投影恢复；
- `scene.restore.checkpoint`：可导入/导出模型私有 checkpoint；
- `scene.restore.topology`：恢复时允许改变 env/layer 拓扑；
- `monitor`：支持 monitor 注册与当前值更新；
- `action.target`：支持 environment/layer/agent target；
- `action.kwargs`：支持 action kwargs；
- `chart.truncate`：支持带时间边界的 chart 删除操作。

v0.3 schema 中存在某字段不等于某个模型必须支持对应能力。例如所有 renderer 都认识
`scene_restore`，但没有 `scene.restore.*` 能力的模型必须拒绝该请求。

### 5.2 `model.id` 与 `instance_id`

`model.id` 是一个非空 opaque string，允许使用任意形式，例如 `flocking`、UUID，或一段
stringified JSON。协议不解析、重排、canonicalize 或比较 JSON 键顺序；身份判断只比较最终
字符串。它必须在同一个模型的重启和端口变化后保持不变，不同模型不得为了复用项目而共享
同一个最终字符串。

namespaced ID 不是要求。只有模型需要分享给其他作者、机构或公共 registry 时，才建议在 ID
中加入作者、机构、模型变体或版本等 namespace 信息，以降低无意碰撞。

`model.description` 默认按支持 LaTeX 的 Markdown 渲染。renderer 必须 sanitize 生成结果，
默认不执行 raw HTML/script；无法渲染的数学表达式应回退显示源码而不是丢失内容。

`instance_id` 标识一次权威运行实例：

- 网络断开和重连时保持不变；
- simulator 进程重启或同一端口换成另一实例时必须变化；
- `reset` 和显式 `init` 不改变它；
- 一个 transport 连接中不得改变。需要改变时必须断开并重新发送 `simulator_info`。

project 和 snapshot 必须保存 `model.id`、`state_schema_version` 和最近一次 `instance_id`。
连接同一端口时不得只按 URL 判断模型。若 `model.id` 不匹配，renderer 必须隔离旧的
scenario/view binding，不得自动 `state_sync` 或 restore；用户可以新建项目，或明确确认
丢弃旧模型状态。`model.id` 相同但 `state_schema_version` 不兼容时，renderer 可以展示
旧 snapshot，但不得把它发送给 simulator 恢复。

这些身份字段是 immutable session info，不属于可变 `metadata_update`。`metadata_update`
中出现同名字段必须被忽略并报告 warning。

## 6. `state_sync` 是同步，不是恢复

`state_sync` 保留独立 message family：

- renderer -> simulator：`state_sync`；
- simulator -> renderer：`state_sync_begin`、普通 create/update/delete replay、
  `state_sync_end`。

它只把 simulator 的权威状态同步到 renderer，**不得改变 simulator 模型状态**。尤其是：

- renderer 报告的 parameter value 不得在 state sync 中写回模型；
- renderer snapshot 不得借 state sync 恢复到 simulator；
- chart 历史不得隐藏在 action kwargs 或 state sync inventory fields 中传回模型。

建议的 request shape：

```ts
interface StateSyncRequest {
  request_id: string;
  model_id: string;
  instance_id?: string;
  state_revision?: string;
  metadata_revision?: string;
  parameters: Parameter[];
  actions: Action[];
  envs: Array<{
    id: string;
    type: string;
    layers: Array<{ layer_id: string; layer_type: string }>;
  }>;
  charts: ChartMetadata[];
  monitors: MonitorMetadata[];
}
```

这些 top-level 字段沿用 v0.2 的扁平 state sync 风格，并加入 identity、revision 与 monitors。
数组是 renderer-held inventory，不是希望写回的状态；尤其 `parameters[*].value` 只能用于判断
renderer 当前持有什么，simulator 不得应用它。简单 renderer 发送空数组并省略 revisions，
simulator 必须能够执行 full replay。

assets 继续通过专用 `asset_sync` 协商，不能塞进 state sync；logs、screenshots 和 chart 历史也
不是 inventory。后续新增 synchronized object family 时，直接增加同级复数字段，不再创建
嵌套 `inventory` object。

boundary 增加明确模式：

```ts
interface StateSyncBeginPayload {
  request_id: string;
  model_id: string;
  instance_id: string;
  mode: "replace" | "reconcile";
}
```

- `replace`：renderer 从空的 model-owned staging state 应用 replay，成功后原子替换；
- `reconcile`：仅允许 request 的 `instance_id` 与当前实例相同，在现有 staging state 上应用；
- request 的实例不一致、revision 不可识别、inventory 全空或 simulator 无法证明增量完整时
  必须使用 `replace`。

`state_sync_end` 必须 echo `request_id` 并给出最终 state revision。begin/end 之间不得嵌套
另一 state sync 或 scene restore。renderer 只在 end 成功时提交 staging state；中途断线或
schema error 必须丢弃 staging state 并保留此前已提交状态。

同一实例的 `reconcile` 默认保留 renderer 已有 chart 历史，只同步 chart definition 和
simulator 明确发出的 chart updates。`replace` 清空旧 chart 历史，除非 replay 显式提供。

## 7. Action v0.3

### 7.1 Action definition

```ts
type ActionScope = "model" | "env" | "layer" | "agent";

interface ActionKwargDefinition {
  name: string;
  label?: string;
  type: "number" | "integer" | "string" | "boolean" | "enum" | "json";
  required?: boolean;
  default?: unknown;
  min?: number;
  max?: number;
  step?: number;
  options?: string[];
}

interface Action {
  id: string;
  label: string;
  scope?: ActionScope;                 // 默认 model
  kwargs?: ActionKwargDefinition[];    // 默认 []
  continuous?: boolean;               // 默认 false，含义见 7.4
}
```

删除 action 的 `allow_runtime_change`（v0.2 alias 为 `allowRuntimeChange`）。它没有清楚的 wire
行为，renderer 对按钮 label、位置、
连续执行等修改属于 view override，不应反向修改 simulator-owned action definition。
parameter 的 `allow_runtime_change` 不在本条删除范围内。

kwargs definition 使用有序数组，避免 object key 顺序决定 UI。definition 中 name 必须唯一。
`json` 是复杂模型的 escape hatch；普通模型应优先使用可直接生成表单的标量类型。

`required: true` 与 `default` 互斥。无 default 的 optional kwarg 在 invocation object 中保持
缺席，renderer 和 binding 不得擅自补 `null`。default 由 simulator 在调用 handler 前应用，
保证 headless renderer 和 browser renderer 行为一致。

### 7.2 Target

```ts
type ActionTarget =
  | { type: "env"; env_id: string }
  | { type: "layer"; env_id: string; layer_id: string }
  | { type: "agent"; env_id: string; layer_id: string; agent_id: string | number };
```

model-level action 不携带 target。其余 scope 必须携带完全匹配的 target。renderer 可以根据
当前环境/选中 agent 构造 target，但 simulator 必须再次检查 env、layer、agent 是否存在且
属于正确类型。不存在的 target 必须返回 correlated `action_result.error`，不得静默退化为
model-level action。

agent/layer identity 使用 target，不建议再把标准 agent ID 当作自由 kwargs。kwargs 用于
例如 `t=0`、`t=43200`、强度或模式等额外参数；这样一个 action 可以服务多种调用，而不必
为每个值创建按钮。

specialized action 示例：

```ts
const action = {
  id: "set_alarm",
  label: "Set alarm",
  scope: "agent",
  kwargs: [{ name: "t", type: "number", required: true }],
};

const invocation = {
  id: "set_alarm",
  request_id: "action-42",
  target: { type: "agent", env_id: "world", layer_id: "agents", agent_id: 17 },
  kwargs: { t: 43200 },
};
```

### 7.3 Invocation 与结果

```ts
interface ActionInvokePayload {
  id: string;
  request_id: string;
  continuous?: boolean;
  target?: ActionTarget;
  kwargs?: Record<string, unknown>;
}

interface ActionResultPayload {
  id: string;
  request_id: string;
  should_continue?: boolean;
  error?: { code: string; message: string; data?: unknown };
  timings?: TickTimingBreakdown;
}
```

renderer 对 kwargs 的校验只用于 UX，simulator 是最终校验方。没有 `error` 即成功；未知
kwarg、缺少 required kwarg、类型不符、target 不符或 handler 抛错都通过同一个可选 `error`
报告，不在 wire contract 中区分 rejected 与一般执行错误。每个被解析的 `action_invoke` 必须
恰好对应一个 `action_result`，包括所有错误；协议 envelope 本身无法解析时才发送独立 `error`。

若 `action_result.error` 存在，renderer 必须忽略同一 payload 的 `should_continue` 并终止当前
连续调度。
binding 应在调用 handler 前完成 target/kwargs 校验，避免输入错误产生部分 mutation；普通
handler 执行错误不承诺自动回滚，已经发出的模型更新仍是可观察结果。

默认每个 instance 同时最多一个 in-flight action。renderer 不得自动重试无结果的 action，
因为 action 不假定幂等。所有可见状态变化和专用 payload 必须在对应 `action_result` 之前发送。
任何 `action_result.error` 必须终止该 renderer 的连续调度。

Action handler 可以发出正常的 param/env/item/monitor/chart 消息。它不得发出伪造的
`state_sync` 或把 scene restore state 内嵌进 action result。

### 7.4 连续执行：view 决定调度，action 声明许可

连续执行是 view property；action definition 的 `continuous` 不再命令 renderer 自动运行。

- view `continuous: false` 可以单次执行任何 action，包括 `continuous: true` 的 action；
- view `continuous: true` 表示 renderer 在每次成功 `action_result` 和 render barrier 后再次发送；
- action `continuous: true` 表示 simulator 声明该 action 支持这种重复调用；
- action `continuous: false`/省略时，renderer 仍可允许用户强制创建连续 view，但必须警告；
  simulator 必须明确执行每个请求或返回带 `error` 的 `action_result`，不使用“未定义行为”描述
  wire 结果。

这个方向是合理的：目前任何连续 action 本来就可以单步执行，说明 action 上的字段从来不
应当是“必须连续”的 UI 指令。`step` 可以声明 `continuous: true`，同时服务单步按钮和连续
运行；简单模型因此可以只实现一个推进 handler。

`action_result.should_continue: false` 是 simulator 对后续调度的 veto；它只影响当前连续 run，
不改变 action definition。

## 8. 保留 action ID 与完整语义

首批保留 ID 只有 `init`、`start`、`step`、`stop`、`reset`。不增加 action role；renderer
按精确 ID 解析内建控件。

保留 ID 并不绕过 ActionSchema。模型可以省略不适用的 action，也可以提供奇怪但合法的
definition。renderer 应允许用户手工创建对应 view，同时对以下情况给出非阻塞 warning：

- `init` 被做成普通或连续按钮；
- 保留 action 不是 model scope；
- 保留 action 有无默认值的 required kwargs；
- `reset`、`stop` 被配置为连续执行；
- view 要求连续但 action 未声明 `continuous: true`。

内建 toolbar 只调用 model scope 且可用空 kwargs 调用的保留 action。

### 8.1 `init`

结论：保留 `init`，但把它定义为 lifecycle hook，而不是 state sync 的别名。

- simulator instance 必须维护 `uninitialized | initialized` 状态；
- 第一个通过身份校验的 `state_sync` 到达 uninitialized instance 时，simulator 在
  `state_sync_begin` 前恰好调用一次 init hook；
- init 先构造权威模型，随后 state sync replay 初始状态；init 本身不发送 `action_result`；
- 短暂 transport 连接但未完成首个 state sync 不触发 init；
- 同一个 instance 的新 renderer 或网络重连不再次触发 init；
- binding 如果在 transport 之前已经构造好模型，可以把 instance 标记为 initialized。

state sync 解决“把已有模型同步给 renderer”，init 解决“模型第一次如何产生”，两者不
重复。当前 binding 在 on-connect 中直接 init 的行为必须迁移，否则重连会重建模型。

若 simulator 注册了可显式调用的 `init` action，手工 `action_invoke(init)` 表示重新按 binding
初始配置构造整个模型，parameter 可以回到初始 canonical values。它必须完整发出由此产生的
param/metadata/env/monitor/chart 专用更新并以 `action_result` 结束。它不改变 `instance_id`。
默认 auto-layout 不为 init 创建按钮。

### 8.2 `step`

一次调用推进恰好一个模型声明的 logical step，然后发出 time、环境、monitor 和 chart 等
变化。若模型没有离散 step，可以不注册。`continuous: true` 时 renderer 可以重复调用它。

### 8.3 `start`

一次调用推进一个 simulator-defined run quantum；它不允许 simulator 启动隐藏的无限循环。
quantum 通常等于一个 step，也可以是模型为吞吐量定义的多个内部 step。连续运行仍由
renderer 逐次发送 `action_invoke(start)` 驱动。

简单 binding 可以让 `start` 与 `step` 调用同一 handler，或只暴露 `step`。toolbar 的 Run
优先使用 `start`，不存在时回退到声明可连续的 `step`；Step 优先使用 `step`，不存在时可对
`start` 做一次单次调用。

### 8.4 `stop`

`stop` 是 run 结束后的模型 hook，不是抢占或取消 in-flight action 的协议。renderer 先停止
调度，等待当前 `action_result`，再调用 stop。干净结束的原因包括用户 pause/stop、条件满足、
达到步数、simulator 返回 `should_continue: false`，以及 reset/restore 前的停机。

断线时 renderer 无法保证发送 stop；重连后不得补发一个可能重复的 stop。没有清理需求的
模型可以不注册 stop。

### 8.5 `reset`

reset 在当前 canonical parameter values 下重建动态模型状态，并把 time 回到模型定义的
初始时间。它不调用 init hook，不改变 `model.id` 或 `instance_id`。

parameter 默认保留当前值。若模型在 reset 时拒绝、归一化或主动改变 parameter，必须通过
`param_sync` 或完整 `param_update` 明确发出；不得依赖 renderer 猜测。

reset 对 chart 没有隐式 renderer side effect。默认 binding 应显式发送
`chart_update { operation: "clear", kind: "all" }`，再发送需要的初始点。
自定义模型若希望保留或 truncate chart，可以发送对应专用 chart operation。环境和 monitor
同样通过各自消息显式替换，所有变化在 reset 的 `action_result` 前完成。

### 8.6 Parameter 生命周期汇总

| 操作 | 默认 parameter 行为 |
| --- | --- |
| 首次隐式 init | 建立 binding 初始 definition 和 canonical value |
| 显式 init | 回到 binding 初始配置；所有变化必须同步 |
| start / step / stop | 保持不变，除非 action 业务明确改变并同步 |
| reset | 保留当前 canonical value；重建动态状态 |
| state_sync | 只读，不得改变 simulator parameter |
| scene_restore | 只应用 payload 中明确包含的 parameter；省略的保持不变 |

## 9. Scene capture 与 restore

### 9.1 与 renderer snapshot 的区别

renderer snapshot 中的环境投影可以完整恢复可见场景，但未必包含 RNG、scheduler queue、
模型私有索引或外部资源状态。因此 v0.3 区分：

- **projected restore**：从 params、time 和完整 environment abstraction 重建；
- **checkpoint restore**：先导入 simulator 私有 checkpoint，再叠加可编辑 projected state。

模型只有在其 binding 能保证投影足够重建后，才可声明 `scene.restore.projected`。需要精确
恢复隐藏状态的模型应声明 `scene.restore.checkpoint`。UI 必须展示恢复等级，不得把视觉上
相同冒充为精确模型恢复。

### 9.2 完整 environment abstraction

scene restore 不复用 renderer 的 `storageSnapshot`。协议定义 transport-neutral shape：

```ts
interface RestorableEnvironment {
  id: string;
  type: "uniform" | "2d";
  layers: Array<{
    layer_id: string;
    layer_type: string;
    dependency_layer_ids?: Record<string, string>;
    metadata?: Record<string, unknown>;
    items?: Array<Record<string, unknown>>;
  }>;
}
```

每个列出的 environment 和 layer 都是完整状态，不是 item diff。对有 item channel 的 layer，
`items` 省略等同空数组；metadata-only layer 可以省略。layer registry 仍决定 item key 和
schema。重复 item key 使整个 restore 无效。

默认 projected restore 只允许把状态放回相同 ID/type/dependency topology 的原始环境。
只有声明 `scene.restore.topology` 才允许创建、删除或改变 topology。

### 9.3 `scene_restore`

```ts
interface SceneRestorePayload {
  request_id: string;
  model_id: string;
  state_schema_version?: string;
  expected_instance_id?: string;
  checkpoint?: {
    encoding: string;
    data: Uint8Array | string;
  };
  time?: number;
  parameters?: Array<{ id: string; value: unknown }>;
  envs?: RestorableEnvironment[];
  // charts 在 schema 中明确禁止
}
```

至少必须包含 checkpoint、time、一个 parameter 或一个 environment。字段省略表示保持当前
状态；空 parameter/environment 数组是 no-op，不表示删除全部。要清空某层 items，必须发送
该完整 environment，并把该层 `items` 设为空。

若同时提供 checkpoint 和 projected overlay，应用顺序固定为：

1. 导入 checkpoint；
2. 应用 payload 中的 parameters；
3. 替换 payload 中列出的完整 envs；
4. 应用显式 time；
5. 重新建立派生索引并校验不变量；
6. 向 renderer replay 最终权威状态。

这支持“从 snapshot 任意时刻恢复”“编辑多个 agent 后恢复”和两者叠加。params 或 env 都可
单独省略。charts 既不传给 simulator，也不被 environment abstraction 隐式包含。

restore 是独立事务：

- renderer 必须先结束连续 run 并等待 in-flight action；
- simulator 必须先完整校验并准备可回滚状态；
- `scene_restore_begin` 后发送权威 param/env/item/metadata/monitor replay；
- `scene_restore_end` echo request ID，并返回 `ok | rejected | failed`；
- renderer 只在成功 end 时原子提交；
- 事务中禁止 chart message，禁止嵌套 state sync/restore；
- 中途断线后结果未知，renderer 必须先 state sync，且不得自动重试 restore。

同一个 `request_id` 在同一 instance 上重复到达时不得再次应用；simulator 应返回缓存结果或
`duplicate_request` error。

### 9.4 Optional checkpoint capture

精确 snapshot 使用专用 `scene_capture` / `scene_capture_result`，不得把 checkpoint 塞进
`action_result`。SnapshotRecorder 只在用户要求可恢复录制且 simulator 声明 checkpoint 能力时，
在 action boundary 请求 capture，并把结果关联到对应 frame/keyframe。

```ts
interface SceneCapturePayload {
  request_id: string;
}

interface SceneCaptureResultPayload {
  request_id: string;
  model_id: string;
  state_schema_version?: string;
  checkpoint: { encoding: string; data: Uint8Array | string };
}
```

## 10. Monitor

monitor 是只有“当前值”而没有时间序列的观测对象。它适合实时结构化值、文本、诊断结构
或非数值状态；需要历史曲线时仍使用 chart。JSON 与 MessagePack 只是 transport codec，
不改变 monitor 的值语义。

消息族：`monitor_create`、`monitor_update`、`monitor_delete`。

```ts
interface MonitorMetadata {
  id: string;
  label: string;
  render_hint?: "auto" | "tree" | "table" | "text";
}

interface MonitorUpdatePayload {
  id: string;
  value: unknown;
  revision?: string | number;
}
```

- `content_type` 完全移除；renderer 在 outer codec 解码后只处理 protocol value；
- `render_hint` 省略或为 `auto` 时：string-keyed object/map 使用 tree，array 使用 table，其余值
  使用 text；MessagePack 中非 string key 的 map 不是合法 protocol value，必须在 codec 层拒绝；
- object/map 可以用 `render_hint: "table"` 请求表格。普通 map 默认显示 key/value 两列；若
  values 都是 record，可以把 key 作为行标识并以 record keys 的并集作为列；
- hint 与实际值不兼容、超出大小/深度限制或渲染器失败时，必须回退到有界的 text/raw view，
  不能丢失当前值或使整个界面崩溃；
- stringified JSON 仍然是 string，默认按 text 显示，renderer 不做猜测性二次解析；
- update 原子替换当前值，不 append；
- 同一 ID 的中间 update 可以在 render 前合并，最后一个值获胜；
- monitor definition 和当前值参与 state sync、Scenario dump 和 snapshot。

metadata 本身不伪装成 monitor message；renderer 可以把 immutable simulator info、可变
scenario metadata、monitor value 和 agent custom data 都交给同一个 ValueInspector 组件。

## 11. Metadata

`metadata_update` 继续承载 time 和模型自定义的可变 scenario metadata。其行为是浅层 patch：
省略键保持不变，`null` 是合法值而不是删除。model identity、协议版本、binding 版本和能力
只能来自 `simulator_info`。

renderer 顶部状态栏增加 Info 按钮，使用统一 ValueInspector 展示：

- model ID/name/description/version/state schema version；
- instance ID；
- protocol 与 binding 版本；
- capability list/details；
- 当前 scenario metadata。

## 12. Chart v0.3

当前按裸 ID 猜 group 或 series 会产生歧义。v0.3 operation 把选择器直接展平为 `kind` 和
可选 `id`，不再嵌套 `target`：

```ts
type ChartUpdateOperation =
  | { operation: "clear"; kind: "all" }
  | { operation: "clear"; kind: "group" | "series"; id: string }
  | { operation: "truncate"; kind: "all"; time: number; inclusive: boolean }
  | {
      operation: "truncate";
      kind: "group" | "series";
      id: string;
      time: number;
      inclusive: boolean;
    };

type ChartDeletePayload =
  | { kind: "group"; id: string }
  | { kind: "series"; id: string };
```

`kind: "all"` 时 `id` 必须缺席；`kind: "group" | "series"` 时 `id` 必须存在且非空。
`chart_delete` 同样不得按裸 ID 猜类型；删除 group 会同时删除其 series，删除 series 只删除该
series。不存在的 kind/id 是幂等 no-op，不能退化到另一种 kind。

`truncate` 的行为严格为：

- `inclusive: true`：删除 `point.time >= time`；
- `inclusive: false`：删除 `point.time > time`。

对同一 series 和 time 的多次 update，后到值覆盖先到值。不存在的显式 kind/id 产生 warning
并 no-op，不得退化到另一种 kind。

action 若需要清除或 truncate chart，必须在 `action_result` 前发送独立 `chart_update` operation；
Action payload 不增加 chart side-effect 字段。

scene restore payload 禁止 chart。renderer 从 snapshot 发起 restore 时提供本地选项：

- 保留当前 live charts；
- 用该 snapshot/frame 的全部 chart 覆盖；
- 把 live charts truncate 到 restore time。

推荐默认值：从 snapshot 恢复时选择“用 snapshot charts 覆盖”；只恢复手工编辑的 environment
时选择“保留”。renderer 在成功 `scene_restore_end` 后、允许下一个 action 前原子应用选择。

## 13. Snapshot project source

project 不再用一个含义过载的 URL 表示所有来源，改为 discriminated source：

```ts
type ProjectSource =
  | { kind: "websocket"; url: string }
  | { kind: "inmemory"; model_id: string }
  | { kind: "snapshot"; snapshot_id: string };
```

“基于快照创建项目”复制当前 active snapshot 到新项目，并以该 snapshot 的 active frame 作为
初始场景。snapshot source 是 renderer event source，不伪装成 live simulator：

- `start`：播放录制 frame；
- `step`：前进一个原子 frame；
- `stop`：暂停播放；
- `reset`：seek 到 initial frame；
- `init`：保留为内部 lifecycle，不自动生成按钮；
- parameter 编辑和自定义 action 默认只读/disabled；
- 默认只合成并支持上述 builtin control，不重放任意自定义 action 的副作用。

snapshot frame 中的 simulator messages 通过现有 replay path 应用，不创造新的 wire shape。
初始 keyframe 通过 Scenario load/source API 装载，而不是伪造一次发往不存在 simulator 的
`state_sync`。snapshot source project 可以正常修改和保存 view。

从 snapshot source 浏览场景与把 snapshot 恢复到 live simulator 是两条独立路径；后者必须
回到兼容 `model.id` 的 live project 并发送 `scene_restore`。

## 14. Robustness 与并发规则

1. `state_sync`、`scene_restore` 同时最多一个，且不得嵌套。
2. restore、reset 前 renderer 必须停止调度并等待 in-flight action；simulator 仍须拒绝 busy
   请求，不能只依赖 renderer 守规矩。
3. action/state transaction 的 `request_id` 在 instance 内唯一。
4. 事务未收到成功 end 前不修改 renderer 已提交状态。
5. action 的增量可以逐条进入 staging/render pipeline，但 snapshot 的原子 frame 以匹配的
   action_result 为边界。
6. reconnect 不自动重试 action、restore 或 parameter change；先 state sync，再由用户决定。
7. simulator 不支持的 capability 返回 `unsupported_capability`，不得接受后静默忽略。
8. custom layer 若要参与 projected restore，必须在 protocol layer registry 中定义完整 state、
   primary key 和 restore validator；否则 renderer 只能展示，不能发送恢复。

## 15. 三端主要工作

### 15.1 Protocol package

1. 把本草案定稿为 `BEHAVIOR.md`，并从 README、schema JSDoc 和生成文档链接到唯一章节；
   发布 npm package 时包含 `BEHAVIOR.md` 和 conformance assets。
2. 增加 `simulator_info`、monitor、scene capture/restore、结构化 error schema。
3. 扩展 ActionSchema：scope、kwargs、target 和可选 correlated error；采用
   `action_invoke`/`action_result`、`request_id`/`should_continue`；删除 action
   `allowRuntimeChange`，明确 parameter 字段不受影响，result 不包含 status。
4. 增加保留 action ID 常量及其 schema-level warning helper，不引入 role。
5. 调整 state sync request/boundary，使用顶层 parameters/actions/envs/charts/monitors、
   identity、revision 和 replace/reconcile mode；明确这些 inventory 不可写回模型。
6. 调整 chart 的扁平 kind/id、clear、truncate schema，消除 group/series ID 猜测。
7. 定义 RestorableEnvironment 和 protocol value/binary refinements；采用 layer `metadata` 与
   `asset_metadata`，保留 `env_*`/`param_*` message family。
8. codec 覆盖 JSON/MessagePack 的 protocol value 等价语义和 checkpoint bytes；实现已列出的
   path-aware v0.2 字段 alias，不对模型自定义 map 递归改名；peer version `<0.3` 才启用
   compatibility mode，`>=0.3` 必须走 strict canonical mode。
9. 输出 JSON Schema 或等价语言中立产物，供非 TS binding 校验生成。
10. 建立 conformance traces，至少覆盖：首次 init、同 instance reconnect、换 instance、
    model mismatch、action kwargs/target、action validation/handler error、reset param 保留、
    state sync 不回写、restore 成功/回滚/断线、monitor type inference/last-value-wins、chart
    truncate 边界、legacy alias 冲突、`<0.3` compatibility mode 和 `>=0.3` strict rejection。

### 15.2 Renderer（core + web + adapter）

1. `RendererSession` 增加 simulator_info handshake gate、identity 校验和 capability store，并在
   session 建立时一次性选择 strict/legacy codec mode。
2. state sync 使用 replace/reconcile staging transaction；删除任何 client-wins parameter sync。
3. `Scenario` 增加 MonitorStorage、dump/load/event/revision，并纳入 snapshot recorder。
4. `RunController` 支持 action target/kwargs/optional error、stop hook、step/start toolbar
   fallback，保留 renderer-driven loop 和 render barrier。
5. view 的 `continuous` 成为调度来源；编辑器对危险组合 warning，不禁止高级用户保存。
6. scene restore controller：暂停 run、materialize snapshot frame、生成 transport-neutral env、
   发送 restore、原子提交以及处理结果未知状态。
7. ChartStorage 实现扁平 kind/id、clear/truncate、同 time 覆盖和 snapshot chart policy。
8. 抽象 `ProjectSource`/event source，加入 snapshot source；项目格式从 `url` 迁移为 source。
9. 新建非 React 深递归的 ValueInspector core：按值类型推断 tree/table/text，支持 map table、
   惰性展开、virtualization、rAF coalescing、大小/深度限制和 raw fallback；MessagePack 只在
   outer codec 层解码。
10. monitor view、metadata info dialog、agent custom data 共用 ValueInspector；替换 agent dialog
    每次 render 的 `JSON.stringify` 热路径。
11. 顶部状态栏 Info 按钮展示 simulator info 与 metadata。
12. snapshot 创建项目默认只启用 builtin playback controls，自定义 action 和 param 显示只读。
13. web、Tauri、headless agent 对 identity、restore、monitor 和 snapshot source 保持同一 core
    行为，不建立 app-local 协议分支。

### 15.3 Simulator 与各语言 binding

所有 binding 必须先实现相同行为，再提供语言惯用 API：

1. 连接后先发 simulator_info；binding 自动填写 protocol/binding 版本，模型填写稳定 ID、
   model/state schema version 和 capabilities。
2. init 从 transport on-connect 移到“uninitialized instance 的首个有效 state sync”，并保证
   同 instance 重连不重建模型。
3. state sync 只 replay，不再把 renderer parameter value 写回 simulator。
4. action router 支持 scope/target/kwargs 的声明、校验和 dispatch；输入校验或 handler 执行
   失败都发送带 `error` 的 correlated `action_result`，不区分 rejected 与一般 error。
5. 默认 lifecycle helper 实现 init/start/step/stop/reset 语义；简单模型允许只用可连续 step。
6. reset 默认保留 canonical params，并用专用 chart_update 显式 clear/truncate。
7. monitor builder/emitter 接受 JSON/MessagePack codec 都能表示的 protocol value，不要求调用方
   声明 content type 或传入预编码 MessagePack bytes。
8. scene restore 是 opt-in hook。binding 不得假装自动 projection 一定可逆；只有用户提供
   inverse/restorer 或框架能证明完整时才声明 capability。
9. checkpoint capture/restore 是更高一级 opt-in hook，需绑定 model ID 和 state schema version。
10. full env exporter/restorer 必须校验 env/layer/item identity、topology 和重复 key。
11. 每个 binding 的 mapping/inference 层必须有 exact-output 单元测试：输入一个明确模型，断言
    恰好得到一组 params/layers/actions/charts，逐项确认哪些字段存在、哪些字段不存在，不能只
    用 contains 或数量断言。

mapping 测试矩阵至少包括：

| Binding | 需要锁定的 mapping |
| --- | --- |
| Python | constructor/annotation parameter discovery、include/exclude/default、decorator layer/item projector、不可暴露字段 |
| Go | struct tag params、required/optional field projection、rename/default、agent/edge key、零值与 omitted |
| Julia | `parameters_from_fields`、include/exclude/metadata/rename、auto agent/dict projector、mutable/read-only 字段 |
| JS | `inferConfigFields`/`paramsFromConfig`、显式 field override、env/layer projector、undefined omission |

这些 exact fixtures 应同时验证生成的 protocol payload，并在本包 schema 下 parse；各语言 API
文档不得自行描述不同默认值。

- 首次连接只 init 一次，同 instance 重连不 init，换 instance 会 replace sync；
- state sync 在四种 binding 中都不会改变 simulator params；
- 同端口换 model ID 不会把旧项目状态串入新模型；
- step 可以分别以 one-shot 和 renderer-driven continuous 运行；
- target/kwargs 的缺失、类型错误和不存在对象都有带 `error` 的 correlated `action_result`；
- projected 与 checkpoint restore 在 UI 和 capability 中可区分；
- restore payload 无 chart，renderer 的三种 chart policy 都有边界测试；
- truncate inclusive/exclusive 在 group/series/all kind 上结果一致；
- monitor、metadata、agent data 共用 inspector，连续更新不会造成深 React tree 全量重渲染；
- snapshot source 项目无需 live simulator，并且默认只执行 builtin playback controls；
- Python/Go/Julia/JS mapping tests 对 exact output 和 omitted fields 均有断言。

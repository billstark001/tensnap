# Design discussion: snapshot and frame ownership

Status: proposal for discussion, not a new binding contract or an implemented ownership-transfer API. The audit below describes the current code; it does not claim that all four bindings already provide detached snapshots at every boundary.

## Proposed boundary

Model state remains mutable and model-owned. Projection callbacks may read it and construct temporary records, but a value retained as a diff baseline, replay state, or pending publication must have a stable meaning for its entire retained lifetime.

At that publication boundary, use one of two explicit operations: detach the mutable fields once, or accept ownership of a complete projection whose producer relinquishes all mutable aliases, including nested containers and byte buffers. Allocating a new outer dictionary is insufficient if its nested values still belong to the model. The latter operation would need an explicit API; it must not silently become a precondition of existing projector callbacks.

After publication, binding internals, diff caches, observers, and serializers treat that snapshot as immutable. They may share its unchanged nested values and form patches in new outer records. A later model update creates a new published value for each changed field. Runtime freezing or validation on every read is not required by this proposal; TypeScript `readonly`, a Python tuple, a Go struct, or a Julia immutable struct alone also cannot guarantee that nested mutable values have no aliases.

Serialization should read a published snapshot directly. Encoding-specific binary normalization may change the representation of dedicated binary fields, but should not rebuild the entire ordinary value tree. A frame can be shared among recipients using the same encoding once no producer can overwrite its storage. Ownership is released only when the last asynchronous consumer has finished reading it, which may be later than queue admission or the return of a send method.

Decoded binary views need the inverse rule: retain their input frame while consumers use the views, and copy only when a consumer needs independently mutable storage. Restore callbacks that attach decoded containers to mutable model state must not leave those containers shared with an immutable replay/diff snapshot.

## Current binding audit

| Binding | Current item path | Consequence for this proposal |
| --- | --- | --- |
| Python | `models/layer.py` deep-copies new/changed projections and reuses equal previous records. `models/source.py` does the same for source deltas; full source snapshots are also detached. Seeding `last_items` copies records again, and `models/environment.py` provides separate detached environment copies. | Changed items do not all avoid copying, but unchanged records already do. A full source snapshot followed by cache seeding can detach the same data twice. Distinguish an internal owned snapshot from a public independently mutable snapshot before removing either copy. |
| JS | `bindings/utils.ts` detaches nested fields with `structuredClone`, reusing structurally equal previous fields. `bindings/session.ts` uses those helpers for item emission and diff caches. | Structural equality still traverses nested values. An explicit owned projection or trustworthy revision could avoid that work; arbitrary projectors must retain the safe default. Item handling does not establish an ownership guarantee for every monitor, chart, metadata, asset, or custom emitter path. |
| Go | `abm/layer.go` uses `maps.Clone` for tracker snapshots. `binding/projector.go` creates outer maps but retains selected nested maps/slices. | The current copies are shallow. In-place mutation of a shared nested model map/slice can rewrite the previous baseline and hide a change. Removing copies globally would worsen this; define a safe default and an explicit immutable/owned projection path before optimizing. |
| Julia | Projectors call `_jsonable`; layer normalization calls it again; `_encode` traverses the payload again, and MessagePack adds `_messagepackable`. Dictionaries and ordinary arrays are recursively rebuilt. `_jsonable(::Tuple)` only collects the outer tuple, and `_jsonable(::Vector{UInt8})` returns the same buffer. | Several paths do repeated traversal, while tuple-contained mutable values and byte buffers are not universally detached. Conversion and snapshot ownership need separate responsibilities; a normalized representation is not automatically an owned snapshot. |

The Go nested-alias concern is independent of codecs: encoding a frame promptly can protect that frame's contents, but cannot protect a diff cache that still points into mutable model state. A focused probe seeded `NaiveItemDiffTracker` with a record containing `data: map[string]any`, mutated that nested map in place, and observed zero updates. A separate probe using the current Julia `_jsonable` methods confirmed that tuple-contained dictionaries and byte vectors retain mutable aliases. These observations identify gaps to resolve; this discussion does not change either binding's implementation.

## Transport copies and other paths

- JS WebSocket output currently copies `Uint8Array` into `Buffer`; the browser transport also constructs another `Uint8Array`. A zero-copy send view is safe only with a defined input lifetime and a transport-consumption boundary. A pooled encoder's borrowed scratch view cannot become a pending asynchronous frame without such a lease. The session codec now deliberately returns owned MessagePack output; this change does not remove the transport copies. Separately, the Node JSON receive path can copy an existing `Buffer` before UTF-8 decoding. Decoding that buffer synchronously already produces an independent string, so that intermediate byte copy does not require a new asynchronous ownership convention to remove.
- Python's `BatchedMessageQueue` retains encoded immutable `str`/`bytes`, not model dictionaries. `server.broadcast` encodes before queuing and shares that encoded frame across recipients. This queue is not an additional repeated-deepcopy boundary.
- Go's MessagePack codec copies its pooled encoder buffer into owned output before returning the encoder to its pool. The synchronous emitter encodes and writes a frame, but the tracker may retain nested model aliases long after that call. A snapshot policy and a socket-write policy solve different lifetimes.
- Julia's broadcast currently calls encoding for each client. A later optimization could encode once per distinct policy/encoding and share a stable frame. It must preserve per-client encoding selection, ordering, error handling, and snapshot lifetime.
- JS `createLinkedEndpoints` currently queues the original message reference in a microtask, without cloning it. Thus even a delay shorter than a network send can expose a mutable alias. Native browser `postMessage`, custom emitter callbacks, and recording/worker transfers need their own lifetime audits: passing a reference, structured cloning, and transferring a backing buffer have different ownership effects. A transport-independent declaration must not assume they are interchangeable.
- Monitor values, chart histories, layer metadata, assets, checkpoints, replay caches, and restore inputs can have the same aliasing problem even when item diffing is safe. Audit each retained value and every handoff to user callbacks, rather than adding blanket deep copies at each layer.

## Before adopting the proposal

Keep existing callers safe by default. An opt-in owned/immutable projection path must specify nested alias rules, callback behavior, changed-field or revision semantics, the last consumer's completion signal, and release on error/disconnect. Mutable reusable projection scratch needs a different borrowed lifetime; it cannot be stored in a diff cache.

Before replacing copies, test: mutation after publication but before a delayed send; mutation after send while a diff baseline remains live; multiple recipients and encodings; byte subviews and encoder reuse; tuple/list/map nesting; restore followed by model mutation; failed sends; and mutation from diagnostic/user callbacks. Measure scalar and nested workloads separately, including allocation volume, peak retained memory, unchanged-state scans, and changed-item throughput. The target is one necessary detachment at the mutable boundary, followed by reuse, rather than either repeated deep copies or unchecked sharing.

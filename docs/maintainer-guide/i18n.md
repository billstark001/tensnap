# Internationalization (i18n)

## Overview

TenSnap uses [LinguiJS](https://lingui.dev/) for internationalization. The active i18n pipeline spans `packages/tensnap-web`, `packages/tensnap-tauri`, and `packages/web-adapter`, with the web package acting as the main source of truth for shared application strings.

## Supported Languages

TenSnap currently supports three languages:

- **English (en)** - Default language
- **Chinese (zh)** - 中文
- **Japanese (ja)** - 日本語

## Architecture

The current setup has three Lingui configuration files:

- `packages/tensnap-web/lingui.config.js`
- `packages/tensnap-tauri/lingui.config.js`
- `packages/web-adapter/lingui.config.js`

`packages/tensnap-web` owns the main app catalogs. `packages/tensnap-tauri` reuses the web catalogs for the desktop shell and adds its own renderer-side strings. `packages/web-adapter` maintains a separate catalog for its own filesystem/integration UI.

### Configuration

Each package with UI components has a `lingui.config.js` file that configures:

- Supported locales
- Source locale (English)
- Catalog path (translation files location)
- Format (PO format for translation files)

### Translation Files

Translation files are stored in `src/locales/{locale}/messages.po` for each package:

```
packages/tensnap-web/src/locales/
├── en/
│   ├── messages.po    # Source translations
│   └── messages.mjs   # Compiled translations
├── zh/
│   ├── messages.po    # Chinese translations
│   └── messages.mjs   # Compiled translations
└── ja/
    ├── messages.po    # Japanese translations
    └── messages.mjs   # Compiled translations
```

### Language Detection

The language is detected on application startup in the following order:

1. URL parameter (`?lang=xx`)
2. Persisted `locale` setting
3. Browser/System language
4. Default to English

The detected language is stored in the shared settings store. The browser host
uses a guarded localStorage persistence adapter; the desktop host injects a
Tauri `plugin-store` adapter, so WebView storage is not used by Tauri.

## Development Workflow

### Adding New Translations

1. **Mark translatable strings in components:**

```tsx
import { msg } from '@lingui/core/macro';
import { Trans } from '@lingui/react/macro';
import { useLingui } from '@lingui/react';

function MyComponent() {
  const { _ } = useLingui();
  
  return (
    <div>
      {/* For JSX content */}
      <h1><Trans>Hello World</Trans></h1>
      
      {/* For attributes */}
      <input placeholder={_(msg`Enter your name`)} />
    </div>
  );
}
```

2. **Extract messages:**

```bash
cd packages/tensnap-web
pnpm i18n:extract
```

This extracts all translatable strings from the source code and updates the `.po` files.

3. **Add translations:**

Edit the `.po` files in `src/locales/` to add translations:

```po
#: src/components/MyComponent.tsx:10
msgid "Hello World"
msgstr "你好世界"  # Chinese
# or
msgstr "こんにちは世界"  # Japanese
```

4. **Compile translations:**

```bash
pnpm i18n:compile
```

This compiles the `.po` files into `.mjs` files that can be imported at runtime.

5. **Test your changes:**

```bash
pnpm build
pnpm test
```

### Translation Guidelines

1. **Use meaningful IDs**: LinguiJS uses the English text as the message ID by default
2. **Context matters**: Provide context in comments when the same English word might need different translations
3. **Keep translations concise**: UI space is limited, especially for buttons and labels
4. **Test in all languages**: Always test your UI with different languages to ensure proper layout

## User Features

### Changing Language

Users can change the language in two ways:

1. **Settings Dialog:**
   - Open Settings (Tools → Settings)
   - Select desired language from the Language dropdown
   - The language changes immediately

2. **URL Parameter:**
   - Add `?lang=xx` to the URL (e.g., `?lang=zh` for Chinese)
   - This overrides the saved preference

### Language Persistence

The selected language is automatically saved through `SettingsPersistence` and
will be restored on the next launch. In the desktop app it lives in the Tauri
app-data store rather than browser localStorage.

## Package Structure

### tensnap-web

Main web application with full i18n support:

- UI components (MenuBar, SettingsDialog, AboutDialog, etc.)
- Settings management (language selection)
- i18n initialization and provider setup

### tensnap-tauri

Desktop wrapper around the web renderer:

- Reuses the web app locale model
- Registers its own desktop-specific locale bundles
- Must keep the same Lingui macro transform/build pipeline as the web package

### web-adapter

Browser-side filesystem and integration helpers:

- Owns its own catalog for adapter-specific UI
- Shares locale conventions with the web package
- Does not replace the web package as the source of truth for common strings

## CLI Commands

In the `tensnap-web` package:

```bash
# Extract translatable strings
pnpm i18n:extract

# Compile translations for production
pnpm i18n:compile
```

## Best Practices

1. **Always extract and compile**: After adding new translatable strings, run extract and compile
2. **Commit compiled files**: The `.mjs` files should be committed to the repository
3. **Keep .po files clean**: Don't manually edit extracted comments, let the CLI handle them
4. **Test translations**: Build and manually test the application with different languages
5. **Use Trans for JSX**: Use `<Trans>` for JSX content and `_(msg``)` for string attributes

## Adding a New Language

To add support for a new language:

1. **Update lingui.config.js:**

```js
module.exports = {
  locales: ['en', 'zh', 'ja', 'fr'], // Add new locale
  // ...
};
```

2. **Update i18n.ts:**

```ts
export const locales = {
  en: 'English',
  zh: '中文',
  ja: '日本語',
  fr: 'Français', // Add new language
};
```

3. **Extract messages:**

```bash
pnpm i18n:extract
```

4. **Translate the new .po file** in `src/locales/fr/messages.po`

5. **Compile translations:**

```bash
pnpm i18n:compile
```

6. **Update settings store type** in `src/store/settings.ts`:

```ts
type Locale = 'en' | 'zh' | 'ja' | 'fr';
```

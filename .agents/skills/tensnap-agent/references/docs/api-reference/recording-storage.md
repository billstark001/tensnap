# Recording storage and reader contracts

`@tensnap/core/persistence` exports `RecordingStoreBackend`, `RecordingStoreWriter`, `RecordingStoreReader`, `rebuildRecordingStoreIndex` and `RecordingPlayback`. The core entry point imports no filesystem or DOM host. Existing project files, `tensnap-recording` v1, SnapshotArchive, synchronous SnapshotPlayer and one-shot encoders keep their released contracts; the incremental store is a separate format.

## Portable recordings and frame evidence

Single-file recordings use `kind: "tensnap-recording", version: 1` in JSON or MessagePack. Known asset, screenshot and checkpoint fields normalize to owned bytes on import; user-defined strings are preserved. Content detection selects the decoder, including JSON received as bytes. `FrameManifestSchema.state.path` accepts `state.recording.json` or `state.recording.msgpack` with the file's SHA-256; restore/compare follow this path and accept mixed encodings. The manifest remains version 1.

Optional `undefined` object properties are omitted before MessagePack segment encoding, so JSON and MessagePack preserve the same schema. Undefined array entries remain invalid. MessagePack archive segments and resources remain binary; the segment layer does not add base64. JSON uses base64 where binary representation is needed.

Automatic agent recordings have one lifecycle entry for ID, format, recording/pending/persisted/failed status and report. Startup scans legacy flat files and new `recordings/id-<URI-encoded-id>/recording.tensnap-recording.<json|msgpack>` directories before accepting work. Publication renames a complete nonempty directory, atomically reserving an ID across formats and concurrent writers. Existing files cannot be replaced; explicit user-selected exports retain ordinary atomic replacement semantics. Pending manual and bounded recording writes share the same admission limit. Disconnect/stop settle actions, finalize the recorder and drain writes even if later checkpoint cleanup fails. This is a normal-completion/atomic-publication guarantee, not fsync or single-file crash-tail recovery.

The agent's `--recording-format json|msgpack` selects this single-file encoding and defaults to JSON. It does not select image encoding, wire encoding, incremental store encoding or CLI result encoding. GUI recording/frame exports use the project's JSON/MessagePack preference. See the [runtime guide](../user-guide/agent-runtime.md#recording-and-fixed-frame-workflow) and [core persistence API](https://github.com/billstark001/tensnap/tree/main/packages/core#persistence-and-owned-frames) for ownership, validation and export contracts.

Portable encoding transfers the completed recorder snapshot, avoids a second whole-scene clone during frame capture, and borrows immutable history only inside synchronous encoding. Mutable binary/asset envelopes are copied; public detached snapshot and asset-extraction contracts remain unchanged. JSON encoding avoids a whole-archive clone and RLE uses typed buffers. These changes address part of issue #36 without changing archive formats or introducing incremental crash recovery; full decoded archive retention and store boundary encoding remain separate concerns.

## Format and host ownership

The root is MessagePack with `kind: "tensnap-recording-store"`, `version: 1`, a monotonically increasing generation, recording identity, retention mode, first/last/observed frame, count, status, model identity, encoded storage accounting, initial/latest segment references and an optional summary reference. Each immutable boundary contains an independently restorable current scene, stream chunk, previous-boundary reference, assets, optional original provenance/checkpoint, action/source metadata and annotations. Frame IDs are contiguous nonnegative integers within a store; exported ranges may begin above zero. Model time may be absent, repeated or decrease.

Objects use SHA-256 references over gzip-compressed MessagePack bytes, with encoded and decoded lengths and `codec: "msgpack+gzip"`. Reads check lengths/hash before decode and cap individual decoded objects at 64 MiB. Assets are content addressed and deduplicated. Current monitor values and latest chart samples belong to boundary state; chart updates and normalized logs, including their original timestamps, belong to independent stream chunks. Full chart/log output reads only actual stream changes. Stream chunks link to their preceding stream hash, and each boundary references its current tail; missing index rows therefore fail rather than silently shortening history. Full chart/log output reconstructs the requested prefix. A rolling initial baseline includes the retained current stream state. No checkpoint from an older boundary is assigned to a new range origin.

`segments/<16-digit-frame>` are immutable frame/time/request descriptors. Host-native indexes provide frame/time/request selection and a separate chart/log stream-change index and ordered keyset pages of at most 64 rows. The small root never contains a growing segment list. Immutable `roots/<generation>` support reader pins; obsolete roots are pruned in bounded batches. Roots are published only after the referenced objects, descriptor and index entries have completed. A failed append can leave uncommitted objects/descriptors; the previously published root remains authoritative.

Incremental Node stores require the built-in `node:sqlite` module. Node 22.13 removes its experimental CLI flag; use an unflagged runtime such as Node 22.13 or newer in the 22.x line, or Node 24+. The existing non-store CLI retains its Node 22 requirement. See the [Node 22.13 CLI documentation](https://nodejs.org/download/release/v22.13.0/docs/api/cli.html#--experimental-sqlite).

The Node host, exported from `@tensnap/agent/runtime`, uses `NodeRecordingStore(directory)`: immutable objects/descriptors/old roots live in `objects.sqlite`; the rebuildable derived B-tree lives in `index.sqlite`; `root` is replaced by a same-directory temporary-file rename. SQLite WAL uses normal synchronization. A transactional PID/token lease admits one writer, including atomic dead-writer reclamation, and generation pin files protect live readers. Logical index loss can be rebuilt from immutable objects; deleting or physically corrupting the object database loses history. The implementation guarantees committed-prefix recovery after process interruption, and makes no OS-crash or power-loss durability claim. Close the backend after all its readers/writer finish.

`IndexedDBRecordingStore(owner, recordingId)` is exported from `@tensnap/web-adapter/adapters`. Its owner/recording compound keys isolate stores in IndexedDB. Root replacement and index rebuild use transactions; Web Locks enforce live writer ownership and generation pins, releasing pins when a tab exits. Web Locks support is required. The Web/Tauri offline project host accepts a local JSON link with exactly `kind: "tensnap-recording-store-link"`, `version: 1`, `owner` and `recordingId`; it opens the corresponding browser-owned store without materializing its complete timeline or connecting its model source. The link refers to storage in that browser origin/profile; it does not embed or transfer the store. Existing portable recordings remain the portable interchange option.

## Writer, reader and resource limits

Create a writer with an explicit ID and `full-history|rolling` mode. Rolling requires `maxFrames`. Optional writer limits are `maxSegmentBytes` (default 4 MiB), `maxPendingBytes` (8 MiB), `maxPendingSegments` (2), `cacheBytes` (1 MiB) and `maxStoredBytes`. `append()` synchronously encodes/owns the atomic input before its first asynchronous step. It resolves after root publication; atomic frames are not split. Callers cannot mutate a queued input through their original references. After the initial boundary, any scene with charts/logs requires its atomic `frame` message span; a metadata-only boundary supplies an empty span. Queue overflow, an oversized atomic frame, storage exhaustion or I/O failure fails explicitly, leaving the prior committed prefix. Autonomous sources that exceed a held boundary fail instead of silently dropping messages.

Collection holds future action dispatch through capture and storage, with a stop/health check before release. Its live chart/log window is explicit. `maxSegmentBytes` and pending bytes count uncompressed owned input; `storedBytes` and `maxStoredBytes` count actual encoded immutable objects, frame descriptors, manifests and the current root. Host database indexes, WAL pages, allocator overhead and reader pin files and lease records have additional host storage costs. The limit is an encoded payload budget rather than a quota on filesystem allocation. Failed final-summary publication can leave the prior root open; the operation reports persistence failure and recovery reports an interrupted/incomplete store.

Memory scales with the active scene/history window, one atomic input, bounded queue, bounded decoded cache, bounded reference index and requested output. `cacheBytes`/cache metrics count decoded payload bytes, not JavaScript heap or RSS. Node also uses fixed-size SQLite page caches. An explicit large scene, atomic frame or full chart prefix determines its own necessary memory/output cost. A host that keeps unbounded live history cannot claim total memory is bounded merely because it uses a store.

A reader pins one immutable generation. `select({frame})`, `select({time, match})` and `select({requestId, match})` return actual locations. Time supports `first|last|before|after`; request supports `first|last`. Before/after choose the closest eligible time and the last/first frame at that time. `query(frame, spec)` reads only its independent baseline, uses the same bounded selector as live Scenario queries and returns owned results. Cached baseline objects are validated once and stay private. Caller mutation of query/options cannot alter a pending read or cached history.

`readFrame(frame, {history: "active"|"full", signal})` returns an owned CapturedFrame with assets and an optional checkpoint. `active` reads the independently restorable scene window; `full` also reads the necessary chart/log prefix. `range(from, to, {history, signal})` shares the reader cache and advances stream state once, while each returned complete output has its own output cost. Environment-only rendering requests `active` history and avoids unrelated chart/log prefix reads. `exportRange(writer, from, to, signal)` streams bounded inputs to another store and preserves original provenance. Always close reader pins in `finally` blocks.

`RecordingPlayback(reader, dispose?)` gives one tab an asynchronous Scenario, `seek`, `step`, `reset` and `close`. New seeks or steps cancel older pending navigation, including an unfinished step index lookup. AbortSignal stays live across waits; a stale/cancelled result cannot replace the selected scene. Each tab owns its reader/generation and closes its backend through the optional disposal callback. `close()` synchronously cancels reads and resets the owned Scenario, revoking image URLs, then returns one shared cleanup promise. Repeated calls join that promise, including its failure. Reader failure still runs backend disposal; multiple cleanup failures are retained. Closed playback rejects further navigation. `SnapshotPlayer` and `SnapshotPlaybackSource` likewise expose an idempotent synchronous `close()`; callers must close them after use. Project closure, source replacement and failed project initialization release playback and project scenes independently.

## Recovery and garbage collection

`recover()` checks the contiguous committed index/segment chain, stream chunks and asset objects. It returns committed range, verified recoverable prefix, observed/uncommitted tail, live writer ownership, superseded-generation state and explicit errors. An unfinalized generation reports an unknown tail when later observations may not have reached storage; it is marked interrupted only when no writer is alive and it remains the latest generation. It stops at committed corruption rather than jumping across a hole. `rebuildRecordingStoreIndex(backend)` acquires the writer lease, verifies committed descriptors and their closure, then atomically replaces only the derived index. It never rewrites historical segments or starts model actions.

`writer.collect()` requires a drained writer and protects every pinned generation before deleting obsolete rolling data. Full-history collection only prunes obsolete roots and never builds a history-sized in-memory reachability set. Rolling collection's reachability index is proportional to retained/pinned windows; a long-lived pinned reader can intentionally delay disk reclamation. Collection batches rolling GC rather than rescanning the window on every frame. Host teardown releases its readers; cleanup failure is surfaced rather than describing uncollected data as reclaimed.

Legacy single-file readers are eager. Indexed range-I/O and bounded-cache guarantees apply to the new store, and do not remove the output allocation cost of the existing synchronous archive encoders.
